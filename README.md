# AI Admissions Advisor

An admissions Q&A assistant that answers **only** from admissions PDFs uploaded
by teachers. Retrieval runs on Gemini File Search; there is no custom vector
database, embedding pipeline, or RAG framework.

- **Guest** — asks questions, no account needed.
- **Student** — asks questions, keeps conversation history.
- **Teacher** — uploads and manages the admissions PDFs the assistant reads.

## Stack

| Concern | Choice |
| --- | --- |
| App + API | Next.js 16 (App Router), TypeScript |
| Auth + database | Supabase (hosted), Postgres RLS as the authorization boundary |
| Retrieval | Gemini File Search (`@google/genai`) |
| Styling | Tailwind CSS v4 |

## Local setup

### 1. Install

```bash
npm install
```

### 2. Create and link a Supabase project

At [supabase.com](https://supabase.com/dashboard), create a project. Then link
this repository to it — the schema is applied by the CLI, never by pasting SQL
into the Dashboard.

```bash
brew install supabase/tap/supabase     # or see supabase.com/docs/guides/cli
supabase login
supabase link --project-ref <ref>      # the subdomain of your project URL
```

For local development, turn **off** email confirmation under
**Authentication → Sign In / Providers → Email**, so sign-up logs you straight
in without a mail provider. That is a project setting, not schema, so no
migration can carry it.

### 3. Configure the environment

```bash
cp .env.example .env.local
```

Fill in:

| Variable | Where it comes from |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | same page, the publishable key (`sb_publishable_…`) |
| `SUPABASE_SECRET_KEY` | same page, the secret key (`sb_secret_…`) |
| `GEMINI_API_KEY` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| `GEMINI_FILE_SEARCH_STORE` | printed by the bootstrap command below |

`.env.local` is gitignored. The secret key and the Gemini key are read
only on the server and are never sent to the browser.

### 4. Create the File Search store

```bash
npm run gemini:bootstrap
```

This creates a store named `admissions-documents` and prints the resource name.
Copy it into `GEMINI_FILE_SEARCH_STORE`. Re-running is safe — an existing store
is reported rather than duplicated.

### 5. Apply the schema

The local stack runs in Docker and is the proving ground: `db reset` rebuilds
the database from nothing, so a migration that works here will work anywhere.

```bash
supabase start        # ~12 containers on ports 54421-54429
npm run db:reset      # apply migrations from scratch, then seed
npm run db:push       # ship the same migrations to the hosted project
```

`supabase stop` tears the local stack down. Never use `--all`, which would also
stop unrelated Supabase projects on your machine.

Ports are pinned in `supabase/config.toml` (`api 54421 · db 54422 · studio
54423 · smtp 54424 · analytics 54427 · pooler 54429`) and the containers are
namespaced by `project_id`, so this project cannot collide with anything else
running locally. Change the ports there if they clash on your machine.

`supabase/seed.sql` runs on `db reset` only — never on `db push` — and creates
two local accounts: `teacher@example.com` and `student@example.com`, both with
password `password123`.

### 6. Run

```bash
npm run dev
```

Open <http://localhost:3000>. Check <http://localhost:3000/api/health> to
confirm both Supabase and Gemini are reachable; it reports each dependency
separately so a failure points at one thing. Local Studio is at
<http://localhost:54423>.

## Changing the schema

```bash
npm run db:new -- add_something   # create a timestamped migration file
# edit supabase/migrations/<timestamp>_add_something.sql
npm run db:reset                  # rebuild locally and verify
npm run db:types                  # regenerate src/lib/database.types.ts
npm run db:push                   # ship it
```

`src/lib/database.types.ts` is generated output and must not be edited — it is
overwritten on every `db:types`. Application-facing names live in
`src/lib/db.ts`, which imports from it.

## Granting the teacher role

Everyone signs up as a student. Promote a teacher with:

```bash
npm run promote:teacher -- teacher@example.com
```

This uses the secret key, so it needs no database password and no Dashboard
access. There is deliberately no self-serve path to the teacher role, and no
`UPDATE` policy on `profiles`, so a user cannot promote themselves through the
client.

## Project structure

```
src/
  app/
    (auth)/            sign-in / sign-up, server actions
    api/health/        dependency check for local setup
    auth/confirm/      target of the Supabase confirmation email
    teacher/           teacher-only routes (guarded in layout.tsx)
    page.tsx           public chat entry point
  components/          shared UI
  lib/
    auth.ts            session + role helpers
    database.types.ts  GENERATED by db:types — do not edit
    db.ts              application-facing schema names
    documents.ts       document reads
    env.ts             environment access, fails loudly when unset
    gemini/            server-only Gemini client
    supabase/          browser / server / service-role clients
  proxy.ts             refreshes the auth session on every request
supabase/
  config.toml          CLI config: project_id, pinned local ports
  migrations/          schema history, applied by the CLI
  seed.sql             local-only fixtures for db reset
scripts/               one-off setup scripts
```

## Commands

```bash
npm run dev              # development server
npm run build            # production build
npm run typecheck        # tsc --noEmit
npm run lint             # eslint

npm run db:new           # create a migration file
npm run db:reset         # rebuild the local database and seed it
npm run db:push          # apply migrations to the linked project
npm run db:types         # regenerate database types from the local schema
npm run db:diff          # show schema drift

npm run gemini:bootstrap # create the File Search store
npm run promote:teacher  # grant the teacher role to an account
```

## Deployment

Deploy to any Node host (Vercel is the path of least resistance). Set the same
environment variables in the host's dashboard; the hosted Supabase project and
the Gemini API are the only infrastructure required.
