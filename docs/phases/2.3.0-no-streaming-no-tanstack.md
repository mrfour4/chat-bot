# 2.3.0 · Streaming, and why D6 reverses

**Type:** decision · **no code**
**Depends on:** 2.2.1 · **Blocks:** 2.3.1

---

## I recommended TanStack AI. I now recommend against it.

The reason is not TanStack. It is that **we cannot safely stream tokens**, and
streaming was most of what TanStack was buying.

### The conflict

§5.7 layer 3 says: if a response carries no grounding, discard the model's text
and return the refusal instead. `enforceGrounding` can only make that judgement
once it has seen `groundingMetadata`.

Gemini does not send grounding metadata first. It cannot: `groundingSupports[]`
carries a `segment` with start and end offsets **into the completed answer**,
and `groundingChunkIndices` mapping claims to sources. Those are only
expressible once the text exists. The metadata is a statement *about* the
finished answer.

So a streamed answer arrives in this order:

```
token token token token token … token   ← the answer, already on screen
                                 meta   ← whether any of it was grounded
```

Which leaves three options, and only one of them is honest:

1. **Stream, then retract.** The student watches a confident, specific answer type out — "học phí 55 triệu đồng một năm" — and then watches it vanish, replaced by "không có thông tin". They have already read it. They may well believe it. **This is worse than never streaming**: we would have shown the hallucination and then admitted it, which is not the same as never showing it.
2. **Stream, and skip the check when metadata is missing.** This is abandoning the guarantee. Not an option.
3. **Buffer until the response completes, run the guard, then send.** Correct — and buffering to completion *is* not streaming.

We are in case 3. The product's central promise and token streaming are, for
this API, mutually exclusive. The promise wins; it is the whole reason the thing
exists.

### What that does to D6

TanStack AI was going to give us `useChat` with streaming, a defined wire
protocol, and message state. With streaming gone:

| What it offered | Still useful? |
| --- | --- |
| Streaming transport | **No.** We send one JSON response. |
| AG-UI wire protocol | **No.** There is no chunk sequence to standardise. |
| `CUSTOM` events for citations | **No.** Citations are a field in the response body. |
| `useChat` message state | Marginal — `useState<Message[]>` plus one `fetch`. |

That leaves 3 packages, ~4 MB, a pre-1.0 API and a canary transitive dependency
(`@ag-ui/core@0.1.1-canary.beta.0`) in exchange for a `useState` array. Against
this project's stated preference for minimal dependencies, that is not a close
call any more.

**D6 = no.** Hand-rolled: `POST /api/chat` returning JSON, `useState` on the
client. If we later move to a model or API that delivers grounding
incrementally, the route is the only thing that changes.

I want to be clear that this reverses my earlier recommendation, and that the
earlier one was not wrong on the evidence I had — the §5.11 finding (TanStack's
Gemini adapter silently drops `groundingMetadata`) still stands and still
matters. What I had not worked through was that the same metadata's *timing*
rules out streaming altogether, which removes the reason to bring TanStack in at
all.

---

## What replaces streaming

A ~3–6 second wait with nothing on screen feels broken. Since we cannot show the
answer as it forms, we show the *work* as it happens — which is honest, because
those stages are real:

```
⠋ Đang tìm trong tài liệu tuyển sinh…
```

And the answer arrives whole, with its sources already attached — which is
arguably better reading than watching text assemble itself, for an answer whose
entire value is that it is verified.

---

## Outcome

**Decided 2026-08-30.** D6 = no TanStack AI. 2.3.1 implements `POST /api/chat`
returning a complete, guarded JSON answer. No packages added.
