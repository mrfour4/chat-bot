# 4.8 — Vietnamese and English

**Goal.** The interface in either language, switchable, with nothing left
hard-coded.

---

## No locale in the URL

`next-intl` 4.14 (which declares support for `next: ^16.0.0` — checked, not
assumed) is configured **without i18n routing**. The locale lives in a cookie,
read in `src/i18n/request.ts`.

The alternative is a `[locale]` segment, and it would mean rewriting every
route, every `Link`, every `redirect`, and the `requireTeacher()` bounce to
carry a prefix — for an audience that is almost entirely Vietnamese. The cookie
costs none of that, and swapping to routing later does not touch a single
message.

Vietnamese is the default. An English default would make the common case the
one that has to be changed.

## The catalogues

`messages/vi.json` and `messages/en.json`, 131 keys each, namespaced by feature.

**Three tests guard them**, because a missing key does not crash next-intl — it
renders the key itself, so a half-translated catalogue looks like a working page
with a stray identifier in it, which is exactly the kind of failure nobody
reports:

1. both files define exactly the same keys
2. no value is empty
3. **both define the same ICU arguments** for each message

The third caught a real subtlety while being written. English pluralises
(`{count, plural, one {# source} other {# sources}}`) and Vietnamese does not
(`{count} nguồn`) — my first extraction read the plural branches as
placeholders. Only *argument names* count; the branches are English grammar,
not something Vietnamese is missing.

## Validation messages are keys

The schemas in `lib/validation/` now carry keys rather than sentences, because
the same schema runs in the browser and in the server action, and only the
caller knows the reader's language. `useFieldErrors()` translates them for a
form; the actions translate them with `getTranslations`.

`useFieldErrors` passes **every** parameter any validation message can take, on
every call. The alternative — each call site knowing that its password field
needs `min` and its file field needs `size` — puts that knowledge in the wrong
place and breaks silently the day a rule moves.

## Where the line is drawn on server messages

**A message produced while someone is waiting is translated.** There is a
request, so there is a reader whose language we know: authorization refusals,
duplicate uploads, rate limits, "not found", the upload rejections.

**A message a background job persists is not.** An indexing failure written into
`documents.error_message` minutes after the tab closed has no request and no
reader — there is no locale to render it in. Those stay Vietnamese, and so do
the Gemini failure messages behind them.

## The assistant keeps answering in Vietnamese

Deliberate, and worth being explicit about. The documents are Vietnamese. An
English answer would be an **unverified translation of a Vietnamese
regulation** — precisely the kind of unchecked transformation this product
exists to avoid, and its citations would still point at Vietnamese text. The
system instruction and the refusal sentence stay in Vietnamese in both locales.

The interface is bilingual; the evidence is not translated.

## The switcher

`ToggleGroup` — two options, both visible, one click. A server action writes the
cookie and revalidates the layout, because every page renders its own strings on
the server: the whole tree has to be rebuilt, not just the control that was
clicked.

Base UI reports an empty array when the active item is clicked again, so that
case is ignored — a language is always selected.
