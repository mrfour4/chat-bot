# 4.2 — The component inventory

**Goal.** Install what the rest of Phase 4 needs, in one commit, before any of
it starts using them. Nothing here changes behaviour.

---

## Installed

`dialog` · `field` · `collapsible` · `alert` · `empty` · `spinner` ·
`separator` · `skeleton` · `toggle-group`

Three arrived as dependencies of those: `label` and `toggle` (under `field` and
`toggle-group`), plus the `button` the CLI wanted to overwrite.

**`button.tsx` was not overwritten.** The shadcn skill is explicit that
`--overwrite` needs the owner's approval, so the prompt was declined. If the
registry version has since moved on, that is a deliberate, separate decision —
not a side effect of installing a dialog.

## What each is for

| Component | Replaces |
| --- | --- |
| `dialog` | the inline delete confirmation (4.4) |
| `field` | `div` + `label` form scaffolding (4.5) |
| `collapsible` | citations, collapsed by default (4.3) |
| `alert` | hand-styled error and notice paragraphs (4.4) |
| `empty` | three hand-built empty states (4.4) |
| `spinner` | three copies of a bordered spinning `span` (4.4) |
| `separator` | the header's `h-5 w-px bg-rule` divider (4.4) |
| `skeleton` | loading placeholders (4.4) |
| `toggle-group` | the language switcher (4.8) |

`toggle-group` rather than a `select` or a dropdown for language: the shadcn
guidance is that an option set of two to seven choices is a toggle group, and
two languages side by side is one click instead of two.

## Toast, already here and never used

`toast.tsx` was installed at some earlier point and is **not mounted anywhere** —
no `Toaster` in `providers.tsx`, and zero call sites in the app. That is why no
mutation has ever reported success. It exports a `toast` manager and a
`Toaster`; 4.6 wires both up.

## Verification

`npm run build`, `npm run typecheck`, `npm run lint` — nothing imports these
yet, so this proves only that they compile and that the Base UI base is right
(`@base-ui/react/dialog`, not Radix). The real verification is each component's
own phase.
