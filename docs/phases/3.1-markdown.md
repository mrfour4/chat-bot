# 3.1 — Markdown in chat

**Goal.** The model answers in Markdown. We were printing that Markdown as
literal text, so a student saw `* **Phương thức 1:**` instead of a bulleted
list with a bold label.

---

## The choice of library

`react-markdown` + `remark-gfm`. Two direct dependencies.

**Why not `marked` + DOMPurify.** Smaller, but it needs
`dangerouslySetInnerHTML` and a sanitiser standing between model output and the
DOM. `react-markdown` builds React elements directly and **ignores raw HTML
unless you add `rehype-raw`**, which we do not. The text we are rendering comes
from a language model; it should be structurally unable to inject markup, not
merely filtered on its way in. That is the whole argument.

**Why not `streamdown`.** It is built for streaming, and §5.15 rules streaming
out. It would bring shiki and katex for a feature we cannot use.

**Why `remark-gfm`.** Tables, strikethrough and autolinks. Admissions documents
are full of tables — quotas by major, fee schedules — so an answer that
reproduces one should render as a table.

## Where it applies

Both places an assistant message is displayed:

- `src/components/ask-box.tsx` — live answers
- `src/app/history/page.tsx` — saved answers

A student's own question stays plain text. They did not write Markdown, and
rendering it would let a question containing `#` or `*` come back looking
unlike what they typed.

## Decisions inside the component

- **Links open in a new tab with `rel="noopener noreferrer"`.** A link in an
  answer points at something the document mentioned; it should not replace the
  conversation. `noopener` because the target must never reach `window.opener`.
- **Headings are demoted.** The answer sits inside a page that already has an
  `h1`. An `h1` from the model would produce two, so the map starts at `h3`,
  and headings are sized down to something that reads as emphasis inside a
  message rather than as page structure.
- **No `prose` plugin.** Tailwind Typography is another dependency and its
  scale is tuned for articles. The message is ~10 element types; they are
  styled directly.
- **Refusals render through the same component.** They are ordinary prose, and
  a separate path would eventually drift.

## Verification

8 tests in `markdown.test.tsx`, run through `renderToStaticMarkup` — **no jsdom
and no Testing Library added**. The rendered HTML is just a string, so the whole
pipeline is assertable without a DOM, and the vitest `include` grew by one
`.tsx` glob rather than by a dependency.

The tests worth naming:

- **the exact answer shape from your report** — `* **Phương thức 1:**` must
  produce `<li><strong>`, and the syntax must be *gone*, not merely styled
- **raw HTML stays inert** — the security property above, asserted so that
  adding `rehype-raw` for some future formatting convenience fails loudly
- **`javascript:` URLs are stripped**
- **tables render** — without `remark-gfm` this silently degrades to a
  paragraph of pipes, which looks like a model mistake rather than a missing
  plugin

One assertion was wrong on the first run: it expected the word `onerror` to be
absent, but react-markdown *escapes* the tag into visible text rather than
dropping it. That is the better behaviour — the student sees exactly what the
model wrote and the browser never sees an element — so the test was corrected to
assert `&lt;img`.

What tests still cannot say is whether a list *looks* like a list. That is
yours, in the browser: ask *"Có những phương thức xét tuyển nào?"* and the
bullets should be bullets.
