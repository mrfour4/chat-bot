# 2.4.1 · Authorization, verified at the database

**Type:** security verification · **API calls: 0**
**Depends on:** all of 2.1–2.3 · `npm run test:rls`

---

## Why not test the routes

Route guards are UX; RLS is the boundary (§5.4). A test that signs in and calls
an endpoint proves the *guard* — but the guard is not what stops an attacker.
The publishable key is a public value by design and ships in the browser bundle;
anyone can take it and call PostgREST directly, bypassing every route in this
codebase. **The policy is the only thing standing there**, so the policy is what
gets tested.

Each case assumes an identity with `set_config('role', …)` and
`request.jwt.claims`, attempts something that must not work, and asserts on what
the database actually allowed.

## Then I checked the tests could fail

Eleven passes on the first run is exactly when to be suspicious: a test that has
never failed has not been shown to test anything. So I added a deliberately
leaky policy and watched:

```sql
create policy "TEMP_leak" on public.documents for select to anon using (true);
```

```
NOTICE:  with a leaking policy, anon sees 1 document(s)
         -> check would FAIL (good: the test has teeth)
```

Policy dropped, suite re-run, 11/11 green, `pg_policies` confirmed clean. The
green now means something.

## The two cases most worth having

**`student cannot self-promote to teacher`** — `profiles` has no `UPDATE`
policy at all, which is easy to add "helpfully" later while adding a
change-your-name feature. This test turns that into a failure rather than a
silent privilege-escalation path.

**`anon cannot execute handle_new_user`** — the Phase 1 bug that nearly shipped:
Supabase grants `EXECUTE` on new functions to `anon` and `authenticated`
explicitly, so `revoke ... from public` leaves a `SECURITY DEFINER` function
callable by anonymous users. It is now checked on every run rather than
remembered.

## A note on tooling

`supabase db query` accepts only a single statement, so this runs through psql
**inside the project's own database container** —
`docker exec -i supabase_db_admissions-advisor psql …` — which needs no local
libpq install and touches nothing outside this project's namespace (§3).
