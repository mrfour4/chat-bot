# 9.3 — The page, the name and the picture

`/profile`, behind `requireUser()`, which redirects a signed-out visitor to
`/login` — verified: `307 -> /login`.

## Layout

Three stacked sections rather than tabs: picture, details (name, email, role),
and — added in 9.4 and 9.6 — password and ways to sign in. A profile page is
read far more often than it is written, so everything is visible at once and
nothing hides behind a click.

Email and role are shown but not editable, each with a line saying why. A field
that looks editable and refuses is worse than a field that never claimed to be:

- **email** mirrors `auth.users.email`. Letting the copy drift from the source
  would be worse than not offering it; changing it is `auth.updateUser`, which
  re-verifies the address.
- **role** is granted by an admin, and 9.1 spent three brakes making sure a user
  cannot change it.

## The avatar's three fallbacks

```
uploaded image  →  Google picture  →  initials
```

`avatarUrl(user)` returns a signed URL for the stored object if there is one,
otherwise the `avatar_url` (or `picture`) that Google put in `user_metadata`,
otherwise null and the `AvatarFallback` draws initials. Someone who signs in with
Google therefore has a real picture without uploading anything, and it is
labelled as such — "Đang dùng ảnh từ Google" — so the empty "Remove picture"
state is not confusing.

It is wrapped in React `cache()`, so the header and the page share one signing
call per request rather than two. `SessionUser` gained `googlePicture` in the same
place it already reads the auth user, so nothing extra is fetched to find it.

`initials()` takes the first letter of the first and last word, falls back to the
email's first letter, and never returns an empty string. It deliberately does not
strip diacritics: `Đặng Ơn` gives `ĐƠ`, not `DO`.

## Upload is immediate, with an optimistic preview

Choosing a file uploads it — no second "confirm" button, because there is
nothing to decide once you have picked an image. The chosen file is shown at once
via `URL.createObjectURL`, so the avatar changes the instant you choose it rather
than after the round trip.

The file input is `sr-only` behind a real `Button`, the same pattern as the
document upload form in 6.5: a bare `<input type="file">` cannot be styled and
reads badly to a screen reader.

"Remove picture" appears only when there is a stored object — removing a Google
picture is not something this page can do.

## The bug the runtime caught and typecheck could not

`typecheck`, `lint` and 212 tests all passed while every page returned **500**:

```
Error: Only async functions are allowed to be exported in a "use server" file.
Error: Export updateDisplayName doesn't exist in target module
```

The actions file exported `const PROFILE_PATH`. In a `"use server"` module every
export becomes a callable server endpoint, so a non-function export is refused —
and the refusal takes down every other export in the file, which is why the error
that surfaced was the misleading "doesn't exist". The constant now lives in
`src/lib/profile/paths.ts`.

Worth remembering: TypeScript cannot see this rule, and neither can the test
suite. Only running the app does.

## Actions split by responsibility

`actions.ts` holds the name and picture. Password work goes in
`password-actions.ts` (9.4) and identity linking in `identity-actions.ts` (9.6),
rather than one file accumulating every write on the page — the same reasoning
that keeps one component per file.
