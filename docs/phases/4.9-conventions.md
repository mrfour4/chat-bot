# 4.9 — Comments out, conventions written down

**Goal.** No explanatory comments in the source, and a document that carries
what they knew.

---

## How the comments were removed

Not with a regex. A regex that removes `//…` also removes it from inside a
string, a template literal, a URL and JSX text, and the damage is silent.

The stripper parses each file with the TypeScript compiler and collects
`getLeadingCommentRanges` / `getTrailingCommentRanges` around every node.

**Two things it got wrong first, both found by running it:**

1. **`ts.createScanner` returned no trivia at all** with `skipTrivia: false` in
   this version. The first run only removed JSX `{/* … */}` blocks and appeared
   to work — 12 files changed — while every ordinary comment survived. Switching
   to comment ranges on the parsed AST fixed it.
2. **A comment alone in an empty block belongs to no node.** `catch { /* … */ }`
   has no child to own the trivia, so two survived the AST pass. Empty blocks
   are now checked directly.

`{/* … */}` is removed as a whole container, not just the comment inside it —
otherwise an empty `{}` is left behind.

`eslint-disable` survives. It is not an explanation; it changes what the tools
do.

## Where the knowledge went

`CONVENTION.md`. Two sections of it are not conventions at all but **facts that
cost something to learn**, and they were the real argument for writing this
before deleting anything:

- Gemini metadata keys must be lowercase, or `metadataFilter` silently matches
  nothing
- deletion order, and why a 403 counts as success
- `storage.objects` refuses direct SQL deletes
- `updated_at` cannot be backdated, which is what makes it a trustworthy
  liveness signal
- a bulk PostgREST insert sends `NULL` for keys some objects lack
- the answer cannot be streamed, because grounding metadata arrives last

Every one of those looks like something a later reader could simplify away.
Now the reason is somewhere findable rather than in a comment on the line.

The document also states the rule the whole project keeps circling:
**correct behaviour and broken behaviour must not look the same.**

## Verification

`npm test` 91 · `npm run test:rls` 17 · typecheck · lint · build, all clean
after the strip. That the tests still pass is the point: a comment remover that
changes behaviour has removed something that was not a comment.
