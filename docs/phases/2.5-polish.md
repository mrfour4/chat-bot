# 2.5 · States, motion and accessibility

**Type:** polish · **completes Phase 2** · **API calls: 0**

Audited rather than guessed at. Most of the quality floor was already in place
from Phase 1 — a global `:focus-visible` ring in `lacquer`, a
`prefers-reduced-motion` block neutralising CSS animation, `lang="vi"`,
`flex-wrap` layouts — so this phase is the three things that were actually
missing.

## 1 · Smooth scrolling ignored "reduce motion"

The global CSS neutralises CSS animation, but `scrollIntoView({ behavior:
"smooth" })` is JavaScript and sails straight past it. Unrequested scrolling is
precisely the movement that setting exists to prevent, and for someone with a
vestibular disorder it is not a cosmetic issue.

```ts
function scrollBehavior(): ScrollBehavior {
  return window.matchMedia("(prefers-reduced-motion: reduce)").matches
    ? "auto"
    : "smooth";
}
```

A media query in CSS cannot fix a preference that JavaScript is overriding —
the check has to happen where the decision is made.

## 2 · Answers were not announced

Because answers arrive all at once (§5.15) rather than streaming, there is a
single clean moment to announce them — so the message list is an
`aria-live="polite"` region. Without it, a screen-reader user submits a question
and hears nothing, with no way to tell "still thinking" from "finished".

`polite` rather than `assertive`: the answer should wait for a pause, not
interrupt.

## 3 · An empty library looked like a broken assistant

With no documents indexed, every question is correctly refused — and correctly
refusing *everything* is indistinguishable from being broken. The home page
already listed the indexed documents, but a student is not reading a document
list before asking their first question.

Now the chat says so up front, before they spend a question finding out:

> Chưa có tài liệu tuyển sinh nào được tải lên, nên trợ lý chưa thể trả lời câu
> hỏi nào. Vui lòng quay lại sau.

This is the same principle as 2.1.5's post-index check and 2.4.2's forbidden
notice: **the system's correct behaviour and its broken behaviour must not look
the same**. That has been the recurring theme of this whole phase.
