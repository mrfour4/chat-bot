# 9.7 — Five feedback items

## 1. Reset link always failed — and why 9.5/9.6 got it wrong

Every reset link showed *"Liên kết xác nhận không còn hiệu lực."*

`@supabase/ssr` forces `flowType: "pkce"`, and a PKCE reset produces a token
prefixed `pkce_`, which comes back **as a query parameter**, not a fragment:

```console
$ # link from the email, followed
303
location: http://localhost:3000/auth/recover?code=39d7bbac-…&flow=recovery
```

`/auth/recover` read only `window.location.hash`, found nothing, and reported an
expired link — every time.

**The mis-diagnosis is the lesson.** In 9.5 I probed with `curl` against
`/auth/v1/recover` directly. That request carries no PKCE verifier, so GoTrue
issued an *implicit* link with tokens in the fragment, and I built a client page
around a shape our own app never produces. The probe was real; it just wasn't
the code path. Comparing the two flows side by side is what settled it:

| Requested by | Token in email | Comes back as |
|---|---|---|
| `curl` (no verifier) | `token=b8cc98…` | `#access_token=…` fragment |
| our server action (PKCE) | `token=pkce_b9d714…` | `?code=…` query |

So recovery now lands on **`/auth/callback`**, which has exchanged codes since
8.2. `/auth/recover`, `RecoverHandler`, `parseAuthFragment` and its 8 tests are
deleted — they were built for a flow this app does not have, and keeping them
would mean maintaining a second, untested path.

Proven end to end by driving the real server client with a `Map`-backed cookie
jar, which is what makes the verifier survive from request to exchange:

```
1. request reset:                    ok
2. verifier cookie stored:           true
3. link redirects to:                /auth/callback?code=…&flow=recovery
4. code present:                     true
5. exchange:                         ok
6. session user:                     recovery-probe@example.com
7. set new password:                 ok
8. sign in with the new password:    ok
```

**One consequence worth knowing:** PKCE ties the link to the browser that asked
for it. Requesting a reset on a laptop and opening the email on a phone cannot
work — the verifier cookie is not there. So a failed recovery no longer borrows
the OAuth message; `?flow=recovery` gives it its own:

> Liên kết đặt lại mật khẩu không dùng được. Hãy mở liên kết trong đúng trình
> duyệt bạn đã yêu cầu, hoặc yêu cầu một liên kết mới.

Verified: `/auth/callback?code=bogus&flow=recovery` → `/login?error=recovery`,
while the same without `flow` still → `/login?error=oauth`.

## 2. Avatar upload did nothing

The `avatars` bucket migration had never reached hosted:

```
20260831092041   remote: 20260831092041
20260831093411   remote: ""            ← the bucket
```

I pushed after 9.1 and forgot after 9.2, and the app talks to hosted. Pushed,
then verified the whole path against identical local policies:

```
1. sign in:                            ok
2. upload to own folder:               ok
3. record the path on the profile:     ok
4. signed url:                         ok
5. fetch it:                           200 image/png 70 bytes
6. write into another user's folder:    REFUSED -- new row violates row-level security policy
7. sign another user's avatar:          REFUSED -- Object not found
8. upload a gif:                        refused -- mime type image/gif is not supported
```

Check 6 was wrong on the first run: it "passed" because I forgot `contentType`,
so the bucket's MIME list refused it before RLS was ever consulted. A test that
passes for the wrong reason is worse than no test — re-run with the right
content type, it is the policy that refuses.

## 3. "Google" truncated to "G…"

`GoogleMark` carries no size class — deliberately, from 8.3, so `Button`'s own
CSS (`[&_svg:not([class*='size-'])]:size-4`) sizes it. In the connections row it
is not inside a Button, so nothing constrained it: an SVG with only a `viewBox`
expands to the width available and squeezed the label until it ellipsised.

The mark now takes an optional `className`, the row passes `size-5`, and the
label is `whitespace-nowrap` instead of `truncate` — a one-word provider name has
nothing to gain from truncation.

## 4. "Theo hệ thống" wrapped

The dropdown radio item has no `whitespace-nowrap`, so the longest of the three
theme labels wrapped. Fixed at the call site rather than in
`src/components/ui/dropdown-menu.tsx`, so a future `shadcn add` cannot quietly
revert it.

## 5. The header on mobile

Everything sat in one non-wrapping row: logo, four nav links, theme, language,
avatar, role, sign out. Below `md` it now wraps into two rows — logo and controls
on the first, the nav on its own full-bleed row that scrolls horizontally rather
than wrapping mid-list. Order utilities keep the single-row desktop layout
unchanged.

Also shed on small screens: the vertical separator (below `md`) and the
teacher/student badge (below `sm`). The avatar stays, since it is the link to
this page.

Layout is yours to confirm in a real browser — that is what a viewport is for,
and `curl` cannot see it.
