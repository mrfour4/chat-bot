# 2.3.2 · Chat UI (with 2.3.3 · citation rendering)

**Type:** UI · **you verify this in the browser**
**Depends on:** 2.3.1

2.3.3 is folded in: an answer without its sources is not testable as this
product. Shipping a chat that renders answers and *then* adding citations would
have meant asking you to test something we already knew was wrong.

## Decisions

**A refusal looks different from an answer.** Grounded answers sit on white with
a rule border; a refusal sits on `panel` with a `pending` border. Same text
weight, different ground. A student must never mistake "we don't know" for a
quiet, confident reply — and the difference has to survive being skimmed.

**Citations are typographic, not chips.** A left rule in `lacquer`, the filename
and page in mono, the snippet beneath in soft ink. It should read as a footnote
in an official document, because that is exactly what it is: the claim is that
every fact came from an admissions PDF, and this is where the claim becomes
checkable.

**A missing page is simply not claimed.** `trang N` appears only when we have
one. A wrong page is worse than none — a student who checks and finds nothing
there learns the assistant is unreliable, which is the opposite of what a
citation is for.

**The pending state names the work, not a mood.** "Đang tìm trong tài liệu tuyển
sinh…" — with streaming ruled out (§5.15) there is a real 3–6 second wait, and
the honest thing is to say what is happening during it.

**Suggestions disappear after the first question.** They exist to get a blank
page started; once a conversation is running they are clutter competing with
the answer.

**History is captured before the new question is appended**, so the model never
sees the current turn twice. It carries only what was said — retrieval re-runs
every turn regardless (2.2.3), so the conversation can never become a source.
