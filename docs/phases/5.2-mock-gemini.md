# 5.2 — A mock Gemini server

**Goal.** Develop and test everything after this without spending a single
request against the real API, which is out of quota.

---

## 1. Why a server and not a stub

The obvious cheap move is to swap `getGemini()` for a fake object. That would
be wrong for this codebase, because the parts most likely to break are the
parts a stub deletes:

- `classifyGeminiError` reads the **HTTP status and the JSON error body**
  (§5.14). A stub that throws `new Error("quota")` proves nothing.
- The resumable upload is three requests, not one, and `withTransientRetry`
  wraps them.
- `enforceGrounding` and `extractCitations` read the real response shape.

So the mock is a real HTTP server and the real `@google/genai` client stays in
the path. `GEMINI_BASE_URL` points the client at it.

## 2. The five endpoints, read from the SDK

`uploadToFileSearchStore` is a **resumable upload**, so it is two requests, not
one. Read out of `node/index.mjs` rather than guessed:

| # | Request | What matters |
| --- | --- | --- |
| 1 | `POST /upload/v1beta/{store}:uploadToFileSearchStore` | `X-Goog-Upload-Command: start`; the reply must carry an **`x-goog-upload-url` header** |
| 2 | `POST` that url | the bytes; reply must carry **`x-goog-upload-status: final`** and the Operation JSON |
| 3 | `GET /v1beta/{operation.name}` | `operations.get`, polled every 2s |
| 4 | `POST /v1beta/models/{model}:generateContent` | the probe and every answer |
| 5 | `DELETE /v1beta/{documentName}?force=true` | deletion, including the 404 path |

Plus `GET /v1beta/fileSearchStores`, so `/api/health` stays green.

**The detail that makes this work at all** is in `uploadBlobInternal`: when
`httpOptions.baseUrl` is set, the SDK **overwrites the returned upload URL's
protocol, host and port** with that base. Without that, step 2 would go to
Google with our session id. It means the mock can return any URL it likes.

The Operation shape is `{ name, metadata, done, error, response: { parent,
documentName } }` — read from `uploadToFileSearchStoreOperationFromMldev`.

## 3. What it simulates

**Delay grows with the file.** `4s + 6s per MB`, jittered ±30%, hard-capped at
**150 seconds**. Your ceiling was three minutes; the cap sits under it so the
ceiling is never the thing you observe.

**Outcomes are random, and they are the outcomes that actually happen.** Not a
coin flip between "ok" and "error" — the five failures this app has met:

| Outcome | Rate | Exercises |
| --- | --- | --- |
| success | 65% | the happy path |
| `operation.error` | 12% | indexing genuinely failed |
| indexed but **zero chunks** | 8% | §5.12's silent failure — the one that must not read `ready` |
| `429 RESOURCE_EXHAUSTED` | 8% | `classifyGeminiError`, the Vietnamese quota message, `MAX_QUOTA_ATTEMPTS` |
| `503 UNAVAILABLE` | 7% | `withTransientRetry`'s three attempts and `retryDelay` |

Every rate is an env var; set `MOCK_GEMINI_FAILURE_RATE=0` for a demo.

**`generateContent` returns real grounding.** It answers from the documents it
has been given, stamping `docid` into `customMetadata` exactly as the real
service echoes it back, with `pageNumber` and `groundingSupports`. Ungrounded
answers are also simulated, so layer 3 of §5.7 can be seen refusing.

## 4. One bug this uncovered

`INDEXING_TIMEOUT_MS` is 60s and `STALE_AFTER_MS` is 3 minutes. The sweeper
does `resetToPending` then re-runs the job — so if indexing ever ran longer
than the stale window, **the sweeper would hijack a job that was still
working**, and `claimForIndexing` could not stop it, because the reset put the
row back to `pending` first.

Today it holds by luck: 60s < 3min. The rule it holds by is
**`STALE_AFTER_MS` must exceed `INDEXING_TIMEOUT_MS`** — a job that has not
finished by its own deadline is the only kind that can be stale. Now written
down, with a test, and both numbers raised: the 60s cap was chosen in 2.1.0
when indexing blocked the upload request, and 3.6 made it background work,
where a three-minute PDF is not a problem to be timed out.

`INDEXING_TIMEOUT_MS` → 180s · `STALE_AFTER_MS` → 5min.

## 5. Running it

```bash
npm run mock:gemini          # port 4010
# .env.local
GEMINI_BASE_URL=http://127.0.0.1:4010
```

Unset `GEMINI_BASE_URL` to go back to the real API. `/api/health` reports which
one is in use, because a mock you have forgotten about is a worse problem than
no mock.

---

## Checks

- upload → poll → ready, end to end, through the real SDK
- each failure mode reaches the row as its own Vietnamese message
- a zero-chunk index marks `failed`, never `ready`
- delete returns 404 for an unknown document and the row still deletes
- `/api/health` green, and it says `mock`
- `STALE_AFTER_MS > INDEXING_TIMEOUT_MS`, asserted
