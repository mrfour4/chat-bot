# 2.2.2 · Citation mapping

**Type:** pure logic, test-first · **API calls: 0**
**Depends on:** 2.1.5, 2.2.1 · **Blocks:** 2.2.3, 2.3.3

Turns `groundingMetadata` into the `Citation[]` we render and store.

## Decisions

**`documentId` is read through `DOCUMENT_ID_KEY`**, the same constant the upload
writes (`"docid"`, lowercase — §5.3). Importing it rather than repeating the
string is what stops the write and the read drifting apart, which would fail
silently: citations would simply stop resolving to rows, and everything would
still *look* fine.

**One citation per document-and-page.** Retrieval routinely returns several
chunks from the same page; showing "trang 1" four times under an answer is
noise, not provenance. Same-page chunks from *different* documents stay
separate.

**A missing page is `null`, never a guess.** 2.1.0 found `pageNumber` populated
for both text and scanned PDFs, but nothing guarantees it, and a confidently
wrong page reference is worse than none — a student following it would conclude
the assistant is unreliable.

**Snippets trim to a word boundary** at ~200 characters. A snippet cut
mid-word reads as a bug and undermines the citation it is meant to support.

**Nothing assumes a field exists.** `mediaId` was documented and came back
`undefined` on every chunk (2.1.0), which is the standing reminder here.

## Outcome

**Done 2026-08-30.** 8 tests, written first. `npm test` 48 passed; typecheck and
lint clean.

The test that matters most is the one for a chunk carrying no `docid` at all: a
document indexed before the key existed, or by another tool, still has to
render. It degrades to a filename citation rather than throwing.
