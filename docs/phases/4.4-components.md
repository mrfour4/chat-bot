# 4.4 — Primitives to components, one state per file

**Goal.** Stop hand-rolling what shadcn already ships, and stop packing every
state of a feature into one file.

---

## The primitives that were there

`<button>` and `<input>` styled by hand in six places; three separate copies of
a spinner made from a bordered, spinning `<span>`; four hand-styled notice
paragraphs; three hand-built empty states; a `h-5 w-px bg-rule` divider.

Now: `Button`, `Input`, `Spinner`, `Alert`, `Empty`, `Separator`, `Badge`,
`Dialog`.

**Base UI composes with `render`, not `asChild`.** A `Button` that navigates is
`<Button render={<Link href="…">…</Link>} />` — one element, not a link wrapped
around a button.

## Deleting is a dialog now

The inline confirmation is replaced by `Dialog`, which is what you asked for and
also what the action deserves: it is irreversible and it removes the document
from the assistant's knowledge, so the dialog says that in words rather than
just asking "are you sure".

Still not `window.confirm` — browsers let users suppress it permanently, which
silently turns a destructive action into a one-click one.

## One component per file

**Chat** — `ask-box` kept the conversation state and the mutation and became an
orchestrator of seven: `message-list`, `question-message`, `answer-message`,
`thinking-indicator`, `suggestion-list`, `empty-library-notice`, `chat-error`,
`chat-composer`. `forbidden-notice` came out of the home page.

**Documents** — `documents-panel` was 240 lines holding upload, list, status,
preview, delete confirmation, failure and retry. Now: `document-upload-form`,
`document-list`, `document-list-item`, `document-status-badge`,
`document-preview`, `delete-document-dialog`, `document-failure`,
`documents-empty`.

**History** — `conversation-list`, `conversation-list-item`, `history-empty`.

**Layout** — `site-header` gave up its account cluster to `user-menu`.

Empty states are their own components and their own decision: `DocumentList`
and `ConversationList` render `DocumentsEmpty` / `HistoryEmpty` instead of
branching inside a page.

Components moved into feature folders — `chat/`, `documents/`, `history/`,
`layout/` — with `ui/` left flat, because the shadcn CLI writes there.

## A regression I introduced and caught

Splitting the upload form out of the panel meant it no longer knew that an
upload had succeeded, so **the chosen file stayed in the input afterwards**,
looking like it had not been sent.

Clearing on submit would be wrong — that throws the selection away before we
know it worked, so a failed upload would lose the file. The panel now
increments a key on success, remounting the form. Success clears it; failure
keeps it, ready to retry.
