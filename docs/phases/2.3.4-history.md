# 2.3.4 · Conversation history

**Type:** persistence + page · **completes 2.3**
**Depends on:** 2.3.1, 2.3.2

Signed-in users get their questions saved and a `/history` page. Guests do not.

## Decisions

**Guests are never persisted.** §4 gives history to students, and storing a
guest's questions with no account to attach them to would be collecting data we
said we would not. A guest's conversation lives in component state and ends with
the tab — which is also the honest reading of "chat without an account".

**Persisting never fails the request.** `persist()` catches everything and
returns `null`. A storage problem must not turn a good answer into an error on
screen: a lost history entry is a much smaller harm than a lost answer, and the
student can always ask again. The failure goes to the server log, where it is
actionable.

**The client sends back the `conversationId` it was given**, so a whole session
lands in one conversation rather than creating a new one per question. It is
absent for guests, so the server simply does not persist.

**RLS is still the boundary.** `/history` calls `requireUser()` for the redirect,
but the queries run as the user, so `conversations_all_own` and
`messages_all_own` decide what comes back. The page could not show someone
else's conversation even if the route guard were wrong.

**Citations are stored with the answer**, and re-rendered from `messages.citations`
through the same `CitationList`. A saved answer without its sources would be a
different, weaker artefact than the one the student saw.
