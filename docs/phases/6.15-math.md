# 6.15 — Mathematical notation

## What you reported

> **$\text{THPT}_\text{ĐT}$:** Điểm thi tốt nghiệp THPT năm 2026…
>
> These are displayed as raw formula characters, which are difficult for users to
> understand.

The model writes LaTeX. The renderer had no idea what it was, so the reader got
the source: dollar signs, backslashes and braces in the middle of a sentence
about admission scores.

## The change

`remark-math` finds the notation, `rehype-katex` renders it, KaTeX's stylesheet
is loaded once in the root layout. Three packages, no configuration beyond two
options that matter:

```ts
{ throwOnError: false, strict: "ignore" }
```

Both exist because the input is model output, not a document we control. A
malformed formula renders as its own source in red instead of taking the answer
down with it, and KaTeX's warnings about characters it does not know — Vietnamese
diacritics inside `\text{}` are the likely ones — stay warnings.

A formula has no spaces to wrap at, so a long display block scrolls in its own
box, like tables and code already do.

## What the tests pin down

The rendered output keeps the original TeX in a MathML `<annotation>` — that is
KaTeX being correct, for copy-paste and screen readers — so asserting "the source
is gone" would fail on the very markup that proves it worked. The test asserts
the structure instead:

```html
<msub><mtext>THPT</mtext><mtext>ĐT</mtext>
```

and that no `$` reaches the reader. Four tests: the notation from your report,
display blocks, a lone dollar sign left as text, and malformed input that must
not throw. Removing the plugins fails two.

`Đ` renders through KaTeX's Latin fallback, so the subscript reads correctly.

## Verify

- Ask something that returns a formula: it reads as notation, not as source.
- A very long formula scrolls inside the message rather than widening it.
