# 5.9 — Enough data to see the difference

**Goal.** Paging, virtualization, search and filtering are invisible on eleven
rows. This makes them visible.

---

## What it creates

```bash
npm run seed:test -- <teacher-email>          # create
npm run seed:test -- <teacher-email> --clean  # remove exactly what it made
```

| Rows | Exercises |
| --- | --- |
| **80 documents** — 68 ready, 4 uploading, 4 indexing, 4 failed, 4 archived, 4 deleted | 8 pages at 10 per page, every status filter non-empty, search across five universities and eight subjects |
| **60 conversations** | 3 cursor pages at 25, and a list long enough for the virtualizer to actually skip rows |
| **200 messages in the newest conversation** | 8 pages of message paging, so "scroll up for older" can be reached repeatedly |
| **438 messages in total** | the message count on every history row |

Verified after seeding: eight document pages with the last one reachable and
correct, every status filter populated, both searches narrowing, and the long
conversation walking exactly 8 pages of 25 to 200 messages with none repeated.

## Three decisions in it

**Everything is prefixed `[SEED]`, and `--clean` deletes exactly that.** It
runs against the project you are actually using, so "remove the test data" has
to mean something narrower than "empty the tables". The prefix is also visible
in the UI, so nobody mistakes a seeded document for a real one.

**Seeding starts by cleaning.** Running it twice should give you 80 documents,
not 160.

**Archived and deleted rows are `ready` underneath.** That is what they were
before someone archived or deleted them — 5.3's whole reason for keeping the
indexing state separate from the lifecycle timestamps. Seeding them as `failed`
would have been easier and would have quietly modelled a state the app cannot
produce.

## What these documents are not

They have no PDF in Storage and no document in Gemini. They **cannot** affect
an answer — retrieval happens inside Gemini, which has never heard of them — so
the grounding guarantee is untouched.

Two visible consequences, both intended:

- They count towards the chat page's "no documents yet" notice, so it will
  stop showing.
- Previewing one fails, because there is no file. Deleting one works, because
  delete only calls Gemini and Storage when the row names something there.

---

## Checks

- `--clean` removes exactly the seeded rows and nothing else
- running it twice leaves 80 documents, not 160
- every status filter returns rows
- the last document page is reachable and correctly sized
- the long conversation pages back to its first message
