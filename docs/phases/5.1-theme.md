# 5.1 — Theme, switchers, and one sentence removed

**Goal.** Light / dark / system, defaulting to system. Both switchers become
dropdown menus. The chat disclaimer goes.

---

## 1. The sentence

`chat.disclaimer` — "Trả lời chỉ dựa trên tài liệu tuyển sinh đã tải lên" —
is removed from the composer and from both catalogues.

It was added in 4.3 on the reasoning that a claim about the answers belongs
where the question is asked. You have used the app and it is noise: the
citations under every answer already say where the answer came from, and they
say it about *that* answer rather than in general. One sentence repeated under
every question is a worse version of evidence attached to each one.

## 2. Both switchers become menus

`ToggleGroup` was the right shape for two options and the wrong one the moment
there are two of them side by side — four squeezed controls in a 16px-tall
header row. `DropdownMenu` with `DropdownMenuRadioGroup` gives each a trigger,
a checked state and a name, and it is the component the theme switcher needs
anyway (three options, one of which is "System").

`ToggleGroup` stays installed; nothing else uses it yet.

## 3. The palette has to move before it can switch

`--color-paper`, `--color-ink`, `--color-lacquer` and the rest live in
Tailwind's `@theme` block. That block compiles to static values: `bg-paper`
becomes `background-color: #fafaf8`, everywhere, forever. **29 files use these
tokens**, so a dark mode that edited components would be a 29-file diff that
could go wrong in 29 places.

Instead the tokens move to `@theme inline`, referencing plain custom
properties defined twice — in `:root` and in `.dark`. `bg-paper` then compiles
to `background-color: var(--paper)` and resolves per theme. **Zero component
edits**, and the same pattern shadcn already uses for its own tokens two blocks
below.

One new token: `--surface`. Four places hard-code `bg-white` for a raised
surface (both auth forms, the answer bubble, the composer field) — white is
correct on paper and wrong on ink.

### The dark palette

Not a channel inversion. The light palette is warm — office paper, not white —
so the dark one is warm too: a near-black with green-black in it rather than
blue-black, and an off-white that is not #fff.

| Token | Light | Dark | Why |
| --- | --- | --- | --- |
| `paper` | `#fafaf8` | `#131412` | warm near-black, not neutral |
| `surface` | `#ffffff` | `#1c1e1b` | raised, one step off the ground |
| `panel` | `#f1f0ea` | `#212320` | recessed |
| `rule` | `#dedcd3` | `#31342e` | visible without glowing |
| `ink` | `#191a17` | `#eceae3` | warm off-white |
| `ink-soft` | `#6b6c63` | `#a0a297` | 4.5:1 on `paper` in both |
| `lacquer` | `#a32a1c` | `#e8705c` | **brightened.** `#a32a1c` on `#131412` is 2.1:1 — the seal, every citation and the focus ring would fail |
| `lacquer-soft` | `#f4e8e5` | `#2c1d1a` | it is a tinted ground, so it inverts rather than lightens |
| `verified` | `#1f5f4b` | `#5fb99a` | same reason as lacquer |
| `pending` | `#96690b` | `#d3a441` | same |

shadcn's `.dark` block, which arrived from the registry as neutral greys, is
rewritten in these terms so a component pulled from the registry lands on-brand
in both themes — exactly what `:root` already did for light.

## 4. Default is system, and there must be no flash

`next-themes` (`defaultTheme="system"`, `attribute="class"`) writes the class
before first paint from a blocking inline script. `<html>` needs
`suppressHydrationWarning`, because that script edits the very attribute React
is about to check.

The theme is **not** in the locale cookie and not server-rendered. Locale is a
server concern — it decides the rendered strings. Theme is a device concern:
the same account on a phone at night and a desktop at noon wants different
answers, and "system" only means anything on the device.
