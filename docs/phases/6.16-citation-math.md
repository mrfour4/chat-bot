# 6.16 — Notation in citations

## What you reported

> `$\ge50$ | $\ge650$ | $\underline{>}250$ | $>N3$`
>
> The formulas are not rendered correctly.

6.15 taught the answer body to render notation. The citation snippet underneath
it was still `{citation.snippet}` — a plain string — so the same content that read
correctly in the answer read as source in the evidence for it.

## Why not just reuse the Markdown renderer

A snippet is a **quotation from a document**, not a document. Running Markdown
over it would let the quoted text restructure itself: your example is
pipe-separated table cells, and a snippet containing `*`, `#` or `_` would come
out as a list, a heading or emphasis that the source never had. A citation that
silently reformats its evidence is worse than one that shows a backslash.

So the snippet gets notation and nothing else. `splitMath` walks the text and
returns text and math segments; KaTeX renders the math, and every other character
is emitted verbatim. Markdown syntax in a snippet stays as characters, which the
test asserts directly.

## Where a `$` is not notation

Prices exist. The rules that keep them intact:

| Input | Read as |
|---|---|
| `giá $5 và $10 một suất` | text — inline notation may not begin or end with a space |
| `khoảng 5 $ mỗi kỳ` | text — nothing closes it |
| `100\$ một năm` | text, with the escape removed |
| `a $$ b` | text — empty delimiters |
| `$a\nb$` | text — inline notation may not span a line |

Removing that one guard fails two tests.

## A gap the falsification found

The first version of these tests passed while the citation list rendered plain
text again — they tested `MathText`, not its use. Base UI's Collapsible unmounts
its panel when closed, so a rendered `CitationList` contains no snippet at all
and cannot be asserted on.

Rather than add a `defaultOpen` prop that exists only for tests, the entry moved
into `CitationEntry` — which is what "one component per file" already asked for.
Reverting its snippet to plain text now fails a test.
